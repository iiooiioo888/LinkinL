為什麼需要 LinkinL？

不可稽核

雲端 Agent 只有對話紀錄

缺少工具 trace、預算決策與產出物 hash，合規與除錯只能猜。

成本外溢

Token 與 GPU 無閘門

多 Agent 並行時，單次 run 可能燒穿配額；本機也需要 hard stop。

棧碎片化

推理與編排各寫一套

vLLM、LangGraph、向量庫若未在同一敘事下整合，維運成本指數成長。

敘事順序 L04 → L03 → L02 → L01： 由上而下為 AI 執行、預算閘門、共識帳本與 OSS 組件整合。

常見問題

LinkinL 和 Linkin 有什麼不同？

LinkinL 是本機執行版的產品代號與官網（此 GitHub Pages）；可執行的運行時、API 與前端請 clone Linkin 主倉。詳見 #x0c-install 或 getting-started.html。

一定要 GPU 嗎？

否。可接雲端 API 或本機 CPU 推理；GPU 時數由 L03 預算層 metering。

產出物帳本存在哪？

設計上為 append-only ledger（CID + hash chain）；實作可對接本機檔案或 IPFS 節點。

0x0A / TERMINAL · 本機快速開始
$ git clone https://github.com/iiooiioo888/LinkinL.git && cd LinkinL
$ ./scripts/install.sh              # → ./linkin-runtime + linkinl.json
$ cd linkin-runtime && cp .env.example .env
$ docker compose up -d redis chroma
$ python -m backend.main
$ cd frontend && npm run dev
# 後端 :8000 · 前端 :3001 · ./scripts/update.sh · docs/getting-started.html
